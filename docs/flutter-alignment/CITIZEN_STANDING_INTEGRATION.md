# Citizen rating/standing integration - 25 October 2026

This continues C01/P04 using the existing server `trustRating`. It does not
review or replace the report-confidence/trust scoring policy or add AI.

## Data and ownership

- Shared public data lives in lib/models/trust_standing.dart; the existing
  widget file re-exports the type for compatibility. The API client/model does
  not depend on presentation code.
- SyncedUser accepts standing only for active, registered CITIZEN responses.
  CitizenProfile carries it through its mapping/copy methods; guests omit it.
  No raw trustScore is read, stored or displayed and no score is derived from
  report counts. Missing/invalid data stays absent, without a default rating.
- Stars must be finite within the current server's 0.5–5 scale, outOf must be5,
  label nonempty and lowStanding boolean. The next milestone must be complete,
  greater than current standing, within5 and have a positive integer report
  count. Explicit null is accepted only at5 stars. Bad milestones never turn
  into a false highest-standing message. Arbitrary valid fractional stars are
  retained; the client does not snap them to half-star steps.
- Initial login/restore/guest-upgrade already prime the Citizen profile from
  SyncedUser; that existing path now carries standing. Session teardown clears
  it. Refresh uses current Firebase UID plus the bound server account ID,
  generation and request revision. Late successes/failures cannot cross logout,
  owner changes or newer requests. Invalid/missing/error refreshes hide the old
  standing without clearing identity or claiming the device is offline.
- Refresh only changes standing, preserving a newer name edit. Name saves retain
  any newer standing and reject missing credentials/stale sessions rather than
  publishing a local-only success or overwriting another account's profile.
  Broader uncertain-save wording/receipt handling remains separate open work.

## Presentation and freshness

Both empty and populated Citizen Home place one compact, opaque primary-surface
standing card after the reporting hero, matching web's placement. It shows
fractional stars, the server label and server milestone. One accessible touch/
keyboard/screen-reader action opens the existing Citizen Profile route.

The live Profile model supplies the detailed section directly below the hero,
including the existing explanation and a restriction notice only when the
server lowStanding flag is true. The compact Home surface has no restriction
warning. Guests and absent/malformed standing show no stars or fabricated text.
Nothing is added to officer report-review screens.

Home/Profile entry and app resume refresh the standing in the background; Home's
existing Ghana pull-to-refresh refreshes reports and standing together. No new
refresh button or standing-only blocking loader is introduced. A profile that
has never been bound by verified auth sync stays unbound/hidden until that
normal identity path succeeds; this is not a general offline-auth recovery rewrite.
